## 修复：HttpGateway 处理线程池未在 stop() 关闭

承接 11-07 收尾时记录的「唯一剩余候选」。HttpGateway 原每次 start() 就地 new 一个
`ThreadPools.bounded("hellomusic-http", 16, 200, AbortPolicy)` 线程池，stop() 从不 shutdown，
线程池生命周期不对称（线程均为守护线程、进程退出即回收，影响甚微，但资源管理不严谨）。

修法（与 UnixSocketServer 的 connectionPool 字段化处理一致）：
- executor 提为 `private final` 字段，构造时创建一次；
- start() 里 `server.setExecutor(executor)`（去掉就地 new）；
- stop() 在 `server.stop(0)` 之后显式 `executor.shutdown()`。

不改变 HttpGateway 公开 API（start/stop 签名不变），HelloMusicApplication 无需改动。

## 安全：HTTP 控制面 token 鉴权（controlToken）

堵住 README 早已指出的最大实际风险：`config.set` 改音乐库路径 + `/stream/{id}` 组合可读任意文件。
新增 `controlToken` 共享密钥，配置后 HTTP `POST /control` 须带 `Authorization: Bearer <token>`，
否则 401。

设计要点：
- Config.Config 加 `controlToken`（String，无 @Pattern：token 任意字符串，空白视为未配置，
  通过 config.set 传空字符串即可清除令牌）。getControlToken() 去前后空白、空则返回 null（不启用）。
- HttpGateway 构造新增 controlToken 参数；handleControl 在 OPTIONS/方法校验后、读 body 前校验，
  用 `MessageDigest.isEqual` 常量时间比较（防时序侧信道），失败 401 + `WWW-Authenticate: Bearer`。
- 令牌启动时绑定，运行时 config.set 修改仅落盘 + `warnIfRestartRequired` 告警「需重启生效」。
- 数据面 /stream /cover /lyrics 不鉴权（只读媒体、仅读音乐库）；Unix Socket 本机通道不鉴权
  （socket 文件权限已隔离）。
- mergeInto 补 controlToken 合并行（null 保留旧值、空字符串覆盖）。

测试：HttpGatewayTest 新增 4 条（无 token 401 / 错 token 401 / 对 token 200 / 无配置向后兼容 200）。
全量 117/117 通过（113 + 新增 4）。README 配置示例/配置表/端点表/安全提示/顶部风险提示同步更新。

## 架构：HTTP 退化为 Unix Socket 的「外壳」

用户诉求：HTTP 不应是独立的控制实现，而是 Unix Socket 的外壳。原架构里 HttpGateway 与
UnixSocketServer 都直接持有 CommandDispatcher（对等双通道），现收敛为「控制面唯一实现是
UnixSocketServer，HTTP 只是转发壳」。

改动：
- 新增 `UnixSocketClient`：连本机 socket，写一行 JSON、读一行 JSON（每次请求新建连接，
  控制面低频可接受）。
- `HttpGateway`：去掉 CommandDispatcher 依赖，改持 UnixSocketClient；handleControl 把观测到的
  对端地址写入保留字段 `@remoteAddr`（UnixSocketServer.REMOTE_ADDR_FIELD）后转发，
  IOException → 502；httpStatusOf/sendJson 适配 JsonNode（sendJson 参数放宽为 Object）。
- `UnixSocketServer`：新增 `isBound()`；dispatchLine 检测并剥离 `@remoteAddr` 作为
  dispatcher.dispatch 第二参（否则回退 "local"）。
- `HelloMusicApplication`：HttpGateway 改传 `new UnixSocketClient(socketPath, mapper)`；socket
  线程启动后 `awaitSocketBound` 等 isBound（5s 上限，超时仅告警不阻塞）再启动 HTTP，消除启动竞态。
- 类注释与 README（开篇/架构图/特性表/项目结构/设计约定）全面改为「外壳」语义；
  设计约定新增传输层依赖方向：HttpGateway(外壳) → UnixSocketClient → UnixSocketServer → CommandDispatcher，
  HTTP 不得越过 Unix Socket 直接触碰命令分发。

测试：HttpGatewayTest 由「mock dispatcher 直连」改为「起真实 UnixSocketServer(内嵌 mock dispatcher)
+ HttpGateway 指向它」的端到端转发测试；新增 2 条（注入 @remoteAddr 验证 / socket 不可用→502）。
全量 119/119 通过（117 + 新增 2）。
