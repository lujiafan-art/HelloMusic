## 修复：多段 Range 折叠违反 RFC 7233

`HttpGateway.handleStream` 原把多段 Range 折叠成覆盖全部请求段的单一连续区间（min/max），
对 `bytes=0-99,1000000-1000099` 会返回 `0-1000099` 连续数据并谎报单段 Content-Range——返回了
客户端未请求的中间字节，违反 RFC 7233。

修法：多段请求按 RFC 7233 允许的降级策略退化为「只返回第一段、其余忽略」，删除 min/max 折叠
循环（改取 `ranges.get(0)`），复用现有单段流式逻辑；Content-Range 如实只描述第一段。代码注释
与 README `/stream/{id}` 端点描述同步写明「多段降级为第一段，不实现 multipart/byteranges」。

新增回归测试 `multiRangeRequestReturnsOnlyFirstRange`（HttpGatewayTest）：构造 200KB 临时文件，
发 `bytes=0-99,100000-100099`，断言 206 + `Content-Range: bytes 0-99/200000` + 响应体 100 字节
（而非 100100）。全量 112/112 通过（111 + 新增 1）。主源码 javac 零错误。
已提交：commit `20c7472`。

## 修复：ConfigManager.currentIndex 缺下界约束

`Config.currentIndex` 原无 @Min/@Max 注解，越界值被 PlaybackSession.setCurrentIndex 静默忽略——
行为安全但无告警，与其它字段「非法即回退+告警」风格不一致。

修法：
- `currentIndex` 加 `@Min(0)`：负下标在 clearInvalidFields 被拦下并回退为 null（getCurrentIndex
  返回 0），与其它字段一致打印告警。
- `clearField` 补 `case "currentIndex"`（否则告警说「已回退」但值未清空，语义不一致）。
- 上界依赖 playbackQueue 长度，无法用固定 @Max 静态表达，故不设上限；越界（> 队列长度）由
  PlaybackSession.setCurrentIndex 运行时兜底（静默忽略），已在字段 Javadoc 说明。

新增测试 `rejectsNegativeCurrentIndex`：负值被拦下；上界无法静态校验（99_999 不报错）。
全量 113/113 通过（112 + 新增 1）。已提交：commit `22dd647`。
