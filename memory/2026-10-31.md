# 2026-10-31

## 项目代码审查（HelloMusic 全量通读）

对 HelloMusic（纯 JDK 21 本地音乐服务器，无 Spring）做了全量源码通读与代码审查，产出一份问题清单。核心结论：架构分层清晰（控制面/数据面分离、CommandDispatcher 单一入口），但存在注释与实现不符、死代码、极端/边界处理缺失三类问题。

关键发现（供后续修复参考）：
- 幽灵队列项 bug：`PlaybackEngine.next/previous` 先调 `getNextSong()` 已推进 currentIndex，再查曲库；查不到时返回 null 但下标已前进到失效项，与注释「位置未前进」矛盾。
- `QueueManager.addToQueue` 注释声称去重，实际未做 contains 检查。
- `ProgressMapper`/`PlaybackEngine.prepare` 直接用 `meta.getTitle()`，绕过了 `MusicFile.displayTitle()`，导致 "Unknown Title" 占位符不回落文件名（README 约定「显示名唯一实现」形同虚设）。
- 死代码：`ClientSession.isConnected()/getCreateEpoch()`、`MusicFile.displayTitle()/displayArtist()/titleArtist()`、`PlaybackSession.isPreparedFor()`（仅测试用）。
- 历史包袱：`queueSavePath` 配置字段保留但未用；`CommandDispatcher.connect` 硬编码 remoteAddr="unix"，真实对端地址丢失；`PlaybackService` 纯转发门面。
- 边界缺失：`/control` 与 Unix Socket 行协议均无请求体/行长上限（readAllBytes/readLine 可被撑爆）；`newCachedThreadPool` 无界；`Files.walk` 不跟随符号链接，软链音乐漏扫（但 stablePath 又用 getCanonicalPath 处理软链，前后不一致）；未知 sessionId 静默回退到起始会话 0。
- 极端值：`seek/play` 用 `asInt()` 截断超大/浮点入参；`play` 传入超大 duration 会污染权威时钟（percent 恒 0）。

## 修复：幽灵队列项 bug（next/previous 游标停在失效项）

根因：`PlaybackSession.getNextSong/getPreviousSong` 是「计算+推进」一体的变异方法，FORWARD 分支在 return 前已 `currentIndex++`；`PlaybackEngine.next/previous` 先推进下标再查曲库，查不到返回 null 时游标已停在幽灵项上，导致 /current 返回 empty。

修法：把「推进游标」与「跳过幽灵项」合并进会话层，新增带校验谓词的方法
`advanceToNextValid/advanceToPreviousValid(Predicate<String>)`，途中幽灵项**就地移除**，游标绝不停在失效项。原 `getNextSong/getPreviousSong` 改为委托 `advanceTo*Valid(id->true)`，对全有效队列行为不变（既有测试零改动通过）。
- 线性模式（FORWARD/REVERSE）走 `skipLinear(±1)`，用 `Math.floorMod` 环绕 + 移除后按方向回退/不回退一格，正确处理「队尾幽灵回绕」「中间幽灵补位」两类情形。
- SINGLE 走 `advanceSingle`（重读当前，失效则移除顺延）；SHUFFLE 走 `advanceShuffleNext/Previous`（命中幽灵即移除并清空随机回溯栈，避免历史下标错位）。
- 引擎 `next/previous` 统一收敛为 `advanceAndCommit(sessionId, forward)`：`beforeId/sizeBefore` → 推进 → 若 size 变小（清理了幽灵）或位置变化则落盘。修正了原误导性注释。
- 新增 5 项测试：PlaybackSessionTest 3 项（advanceToNextValid/advanceToPreviousValid/removeCurrent）+ PlaybackServiceTest 2 项（next/previous 跳过幽灵且 /current 非空）。全量 111/111 通过。

注：本轮沙箱内 Maven 仍被 Security Center 拦 `.m2` 元数据，沿用「手动 javac + JUnit Launcher」验证（build-manual.sh，TestRunner 编译 classpath 需含 junit-platform-engine + apiguardian-api）。
