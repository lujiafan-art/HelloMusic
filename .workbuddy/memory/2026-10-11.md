## HelloMusic 项目代码评审（未改动任何代码）

### 已确认的严重缺陷
1. **歌单持久化实际失效**：`PlaylistService` 用 `new ObjectMapper()`（未注册 JavaTimeModule）序列化含 `LocalDateTime` 字段的 `Playlist`。Jackson 自 2.12 起会抛
   `InvalidDefinitionException: Java 8 date/time type java.time.LocalDateTime not supported by default`。
   该异常属 IOException，被 `savePlaylists()/loadPlaylists()` 的 catch 静默吞掉 → `playlists.json` 写不进也读不出。
   修复：注入 Spring 托管的 ObjectMapper（已自动注册 jsr310），或 `JsonMapper.builder().findAndAddModules()`。
2. **广播里的 librarySize 恒为 0**：`BroadcastService.broadcast()` 每次都先调 `updateServerInfo()`，而该方法把 `librarySize` 硬编码为 0，覆盖了 `updateLibrarySize()` 的结果。
3. **PlaybackSession 非线程安全**：`ArrayList` + 非 volatile 的 `currentIndex`，被 CLI 线程与多个 Tomcat HTTP 线程并发读写，`setPlaylist()` 的 clear+addAll 非原子。

### 安全
- 无鉴权 + `@CrossOrigin(origins="*")` + `PUT /api/config` 可改 `musicLibraryPaths`/`supportedExtensions`，配合 `/api/stream/{id}` 可造成任意文件读取。
- `/api/music`、`/api/config` 直接返回服务器绝对路径（`filePath`、库路径）。

### 其他
- `PUT /api/config` 在请求线程内同步做全量扫描，可能请求超时。
- 扫描每 5 分钟重算所有文件元数据，且为单线程 `Files.walk`，大库慢。
- `/api/music` 无分页；无 `src/test`（starter-test 已引入但零测试）；无 `src/main/resources`（README 却列出了 application.properties/banner.txt）；README 默认扩展名表与实现不符。

## 首次编译验证 + 修复（同日晚，用户交来 mvn 输出）
- 用户执行 `mvn clean test`（宿主机 `/home/user/项目/HelloMusic`，Linux + JDK21）→ **编译失败**，仅 1 个错误：
  `PlaylistController.java:[123,45] 找不到符号: 方法 body(Map<String,String>)，位置: 接口 ResponseEntity.HeadersBuilder`。
- 根因（我上一轮改「歌单增删返回真实结果」时引入）：Spring 的 `ResponseEntity.notFound()` / `noContent()` 返回 **`HeadersBuilder<Void>`**，
  该接口**没有 `body()`**；只有 `ok()/badRequest()/status(HttpStatus|int)` 返回的 `BodyBuilder` 才有 `body()`。
- 修复：改为 `ResponseEntity.status(HttpStatus.NOT_FOUND).body(...)`，并新增 `import org.springframework.http.HttpStatus;`（与 `MusicController` 既有写法一致），
  同时留了注释说明这个坑。**这是本项目唯一需要注意的 Spring API 陷阱**。
- 重要结论：javac 是全量编译且只报 1 个错 → **主源码其余 16 个文件在语法/符号层面是干净的**。
- 由此推断 5 个测试类此前从未被编译过（`mvn test` 在 compile 阶段就挂了）。已逐行静态核对测试断言与真实实现：
  Xing 偏移 36（帧头 4 + side info 32，MPEG1 立体声）、帧头 `FF FB 90 00` = MPEG1 Layer3 128kbps 44100Hz 立体声无 CRC、160000B/16000Bps = 10s、
  `skipId3v2` 的 synchsafe size 解析、`hasId3v1` 末尾 "TAG"、`PlayMode` 枚举顺序 FORWARD→REVERSE→SINGLE→SHUFFLE、
  `MusicMetadata` 默认值 "Unknown Album"、`MetadataExtractor` 的 `catch (Exception)` 兜底 + `" - "` 分割 —— 均与断言吻合，预期 5 个测试类应全部通过。
- 注意：jaudiotagger 对 0 字节/损坏文件会抛异常，已被 `MetadataExtractor` 的 `catch (Exception e)` 吞掉并走文件名兜底，测试依赖的正是这条路径。
